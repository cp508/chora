# chora — концепт

Лёгкий CLI-органайзер пространства: заметки как контексты, заметки как
таски с дедлайнами, календарь поверх того же хранилища. Всё — plain
markdown, синк — git. Никаких демонов и тяжёлых приложений.

Имя: **chora** (χώρα — «пространство-вместилище», место, где вещи лежат
по своим местам). Бинарник `chora`.

## Принципы

1. **Файлы — источник правды.** Только `.md`, читаются любым редактором
   текста и `cat`/`rg` без инструмента.
2. **Редактор — любой.** `chora` никогда не редактирует текст сам, он
   открывает `$EDITOR` и ждёт выхода. Совместимость — через `$EDITOR`,
   а не через встроенный ввод. Исключение — `event --tui`: маленькая
   форма ввода, которая дописывает секцию в файл дня без редактора.
3. **CLI — композабельный.** Человекочитаемый plaintext по дефолту,
   `--json` для скриптов. Одна команда — одна задача.
4. **Синк — git, автоматом.** Пользователь не делает `commit`/`push`
   руками вообще.
5. **Единый конфиг.** Простая конфигурация в `~/.config/chora/config.toml`
   без лишних параметров. Переменных окружения нет — только конфиг
   и явные флаги.

## Хранилище данных

Корень по дефолту `~/chora/` (переопределяется глобальным флагом `--dir`,
либо значением `chora_dir` в конфиге). Приоритет: `--dir` > конфиг > `~/chora`.
Внутри только `.md` (+ служебный `.git/`). Два раздела:

```
~/chora/
  calendar/
    2026-11-20.md      # эвенты дня, могут быть несколько в файле
    2026-11-21.md
  notes/
    <project>/          # проекты — обычные директории
      ...               # поддиректории по вкусу
      *.md              # внутри ТОЛЬКО md
```

Имена файлов календаря — строго ISO `YYYY-MM-DD.md` (сами сортируются,
без двусмысленности день/месяц). Имена заметок — свободные, но тоже
только `.md`.

Хранилище = git-репо.

## Конфиг

Файл `~/.config/chora/config.toml`. Только эти поля, без окружения:

```toml
[main]
chora_dir = "~/chora"
auto_commit = 10
remote_url = ""
```

- `chora_dir` — корень хранилища. `~/` раскрывается через home-дир.
  Значение должно быть строкой в кавычках (TOML).
- `auto_commit` — интервал автокоммита сессии `chora note` в минутах.
  Флага `--every` нет, значение живёт только здесь.
- `remote_url` — SSH-URL bare-репо на VPS (например
  `"ssh://user@vps/chora.git"`). Пустая строка = без remote, только локальный git.

`chora init` создаёт этот файл с дефолтами, если его нет, и после
выполнения предлагает его отредактировать перед использованием.
Флагов у `init` нет — всё берётся из конфига.

## Формат файла дня (`calendar/YYYY-MM-DD.md`)

Один файл — один день, эвентов внутри может быть несколько. Каждый
эвент — секция `##`, поля — `Time:` и `Duration:`, остальной текст
секции — контекст/описание в свободной форме:

```md
# 2026-11-20

## Встреча по работе
Time: 11:00
Duration: 2h

Контекст в свободной форме: повестка, ссылки, итоги.

## Стоматолог
Time: 18:30
Duration: 45m

Взять полис.
```

Правила парсера:

- Заголовок секции `## <name>` — это title эвента (`name` из TUI = title).
- `Time:` — `HH:MM` (24h), обязательное.
- `Duration:` — `<число><s|m|h>` (`10s`, `45m`, `2h`, можно `1h30m`),
  обязательное.
- Секция без `Time:` — не эвент, а просто текст дня (парсер пропускает,
  не ошибка).
- Пустой день = файл из одного заголовка `# YYYY-MM-DD`.

Почему секции, а не один эвент на файл: дата уже в имени файла,
плодить `event1/event2` нельзя (коллизии имён при синке с двух
устройств), а секции дают читаемый день целиком и чистые git-диффы.

## Формат заметок (`notes/`)

Никакого обязательного формата: любой markdown. Проект = директория,
вложенность — по вкусу. Единственное правило, которое держит сам
инструмент: внутри `notes/` не создаются не-md файлы (шаблоны, индекс
и т.п. — тоже `.md`). Временные файлы редакторов (`*.swp`, `*~`,
`.DS_Store`) отсекаются через `.gitignore`, а не попадают в коммиты.

## CLI

```
chora [--dir <path>] <команда>
  init                        # bootstrap без флагов, всё из конфига
  note                        # сессия: редактор + автокоммит (интервал из конфига)
  notes                       # открыть notes/ в $EDITOR (без сессии)
  new [--date <YYYY-MM-DD|today|tomorrow>]    # создать/открыть файл дня в $EDITOR
  event --date <YYYY-MM-DD|today|tomorrow>    # дописать заготовку эвента и открыть в $EDITOR
  event --tui [--confirm]                     # TUI-форма создания эвента
  show --date <today|tomorrow|YYYY-MM-DD> [--json]
```

- `init` — без флагов: создать конфиг с дефолтами (если нет), создать
  `calendar/` + `notes/` в `chora_dir`, `git init` (если не репо),
  `git remote add origin <remote_url>` (если задан и origin отсутствует),
  проверка identity (`user.name`/`user.email`, предупреждение если нет),
  `.gitignore` для мусора редакторов, стартовый коммит. Идемпотентен:
  безопасно перезапускать после правки конфига.
- `note` — главная команда, см. раздел «Сессия». Интервал — только
  `auto_commit` из конфига, флага нет.
- `notes` — открыть `notes/` в `$EDITOR`, выйти когда редактор закрылся.
  Без автокоммита и без финального коммита (однократное открытие).
- `new` — разовое открытие файла дня: создать по шаблону (`# YYYY-MM-DD`),
  если нет, открыть в `$EDITOR`, по выходу — коммит+пуш.
- `event --date <D>` — создать файл дня, если нет, дописать в конец
  заготовку секции:
  ```md
  ##
  Time:
  Duration:

  ```
  открыть файл в `$EDITOR`, по выходу — коммит+пуш.
- `event --tui` — TUI-форма (см. раздел «TUI»): поля name (→ `##` title),
  date, duration, context. `Enter` дописывает секцию в файл дня,
  делает коммит+пуш и выходит без редактора.
- `event --tui --confirm` — то же, но после создания сразу открывает
  файл дня в `$EDITOR`, по выходу — коммит+пуш.
- `show` — прочитать файл дня, вывести эвенты plaintext; `--json` —
  массив `{title, date, time, duration, context}` для скриптов.
- Глобальный флаг один: `--dir` (переопределить `chora_dir` на один
  запуск). `--json` — флаг команды `show`, не глобальный.

## TUI (`chora event --tui`)

Очень простой TUI по центру экрана, четыре поля:

1. `name` — однострочный input, становится заголовком `## <name>`.
2. `date` — дата `YYYY-MM-DD`, цифры меняются стрелками влево/вправо
   либо `h`/`l`.
3. `duration` — однострочный input (`45m`, `2h`, `1h30m`).
4. `context` — многострочный input, свободная форма.

Навигация между полями — стрелки вверх/вниз либо `j`/`k`.
`Enter` на заполненной форме — валидация (`name` непустой, `date`
валидна, `duration` парсится). Поле времени в форме не спрашиваем:
`Time:` ставится как текущее локальное `HH:MM` в момент создания.
После `Enter` — дописать секцию в `calendar/<date>.md`, коммит+пуш.
`--confirm` — после этого открыть файл в `$EDITOR`.
`Esc`/`Ctrl-C` — выход без записи и без коммита.

## Сессия (`chora note`) — ключевой механизм

Поток:

1. Открыть `$EDITOR <chora_dir>` и ждать выхода.
2. Параллельно тикает автокоммит каждые `auto_commit` минут из конфига:
   `git add -A` → коммит, только если есть изменения.
3. Редактор закрылся → финальный `add + commit + push`, тикер
   останавливается, команда выходит.

Правила:

- Коммит только при изменениях (`git status --porcelain` пуст — тишина).
- Сообщение коммита: `autocommit: <ISO-timestamp>` (+ `final:` у
  финального, чтобы в логе было видно границы сессий).
- Пуш — best-effort каждый тик (ошибки глотаются тихо, офлайн — норма),
  гарантированный пуш — только финальный (его ошибка — видимая).
- `Ctrl-C` по самой `chora note`: тикер и дочерний редактор прибиваются,
  висящих процессов не остаётся. Финальный коммит на `Ctrl-C` — не MVP
  (позже через обработку сигналов).
- Редактор, открытый мимо `chora note`, автокоммита не получает — это
  осознанный трейдофф сессии против фонового таймера. Второй контур
  (systemd-таймер «коммить всегда») — позже, они не конфликтуют.

## Совместимость с редакторами

- `$EDITOR` сплитится как shell-строка (там бывает `code --wait`,
  `hx .`). В Rust — крейт `shell-words`, свой сплит не писать.
- Учитывать `$VISUAL`? Нет: один источник — `$EDITOR`, меньше
  неоднозначности. Пустой `$EDITOR` — явная ошибка с подсказкой.
- GUI-редакторы без wait-флага (`code` без `--wait`) отцепляются сразу —
  сессия мгновенно «завершится». Лечится документацией: для GUI в
  `EDITOR` нужен wait-флаг. Детектить и предупреждать — позже.
- Редактор запускается с cwd = корень хранилища, чтобы относительные
  пути и встроенный файловый менеджер работали.

## Git-синк

- Remote — bare-репо на VPS по SSH (`remote_url` в конфиге).
- Первый запуск пары устройств и любые «странные» состояния — через
  ручной `--resync`-аналог: позже, в MVP конфликты резолвятся руками
  (git их хотя бы показывает, в отличие от bisync).
- Листинги/кэш состояния не хранятся — состояние = сам git.
- Телефон — вне MVP. Задел: тот же git (Termux/MGit), бинарник на Rust
  позже можно собрать под Android.

## Устройство проекта (Rust)

```
chora/
  CONCEPT.md            # этот файл
  Cargo.toml            # bin: chora (clap derive)
  src/
    main.rs             # тонкий диспетчер, вся логика в lib
    lib.rs              # реэкспорт модулей
    cli.rs              # clap derive: команды и флаги
    config.rs           # чтение ~/.config/chora/config.toml (serde + toml + dirs)
    error.rs            # thiserror-типы, anyhow на границе main
    store.rs            # layout: пути calendar/notes/, шаблоны файлов
    event.rs            # парсер секций дня <-> struct Event
    tui.rs              # event --tui форма (ratatui + crossterm)
    git.rs              # add/status/commit/push поверх git CLI
    editor.rs           # запуск $EDITOR (shell-words), ожидание выхода
    session.rs          # note: редактор + тикер автокоммита
    output.rs           # рендер plaintext vs --json для show
  tests/                # golden-файлы парсера + show --json
```

Зависимости MVP: `clap` (derive), `shell-words`, `chrono`,
`serde` + `serde_json`, `toml`, `dirs`, `thiserror` + `anyhow`,
`ratatui` + `crossterm`. Git — через вызов `git` CLI, не libgit2
(меньше связей, поведение 1-в-1 как руками).

Типы MVP:

```rust
struct Event { title: String, time: NaiveTime, duration: Duration, context: String }
```

Конфиг: только файл `~/.config/chora/config.toml`
(`chora_dir`, `auto_commit`, `remote_url`) + явный флаг `--dir`.
Переменных окружения нет. Секретов в конфиге нет (SSH-ключи — системные).

QA на каждое изменение: `cargo fmt --check` → `cargo clippy --all-targets
--all-features -- -D warnings` → `cargo test`. Правила кода —
`.opencode/skills/rust-skills/` (265 правил, применяются точечно).

## Дорожная карта

- **MVP:** `init` (без флагов), `note` (сессия + автокоммит по конфигу),
  `notes`, `new`, `event --date`, `event --tui [--confirm]`,
  `show [+--json]`, формат дня, ISO-имена, конфиг из трёх полей.
- **Позже:** systemd-таймер как второй контур, `--resync`-аналог,
  телефон (Termux/git, сборка под Android), детект GUI-редакторов без wait, обработка
  сигналов для финального коммита на Ctrl-C.
- **Не делать:** свой формат вместо md, свой синк вместо git, демоны,
  облако с аккаунтами, переменные окружения для конфигурации.
